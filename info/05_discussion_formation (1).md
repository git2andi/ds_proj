# Discussion formation

## Overall flow

A typical run should move through these phases:

```text
1. setup
2. opening views
3. option comparison
4. challenge / clarification / response
5. narrowing
6. final commitment
7. outcome
```

The phases are soft control states, not rigid scripts. The router should react to the transcript state.

## Setup

The moderator presents the topic, shared context, and option board. The setup becomes the hard fact base of the simulated world.

## Opening views

Each sim should usually contribute an initial view. This does not have to be balanced round-robin forever, but the beginning should establish each participant's rough preference or concern.

Good opening:

```text
The midday option looks like a decent compromise: cheaper than the direct flight, but not as exhausting as the red-eye.
```

Weak opening:

```text
I agree with what has been said.
```

## Comparison and challenge

The middle phase should contain direct comparisons and socially meaningful reactions:

```text
A is fastest, but C gives almost the same convenience for less money.
```

```text
I understand the cheap option, but the overnight timing conflicts with our comfort goal.
```

A good discussion should not be only independent preference statements. Sims should respond to each other.

## Question handling

Questions should create obligations. A direct question to a named participant should usually be answered by that participant before the discussion moves on.

The system should track:

```text
speaker who asked
person addressed
question text / option focus
answered or pending
```

## Narrowing

Narrowing should not happen only because a fixed turn count was reached. It should happen when enough visible evidence exists:

```text
some options are clearly rejected
one or two options are plausible finalists
open questions are resolved or acknowledged
participants have had a chance to state concerns
```

## Final commitment

Final votes should be explicit:

```text
I vote for Option C.
C works for me as the final choice.
Let's choose C.
```

Conditional statements should remain non-final:

```text
I can support C, but only if...
Maybe C works.
I lean toward C.
```

## Bounded unresolved

Unresolved is a valid outcome. It should not be treated as a failure if the transcript visibly supports it. However, unresolved should come after a clear process: split preferences, one compromise attempt if appropriate, and no visible majority.
