# Decide which accessibility features to prioritize in a campus app

A campus app is being developed to improve accessibility for all students and staff. The group must prioritize which accessibility features to implement first, considering usability, technical complexity, and impact on diverse user needs.

## Options

- A) Voice Navigation and Commands — feature type: voice control; technical complexity: medium; user groups benefited: visually impaired, mobility restricted; implementation time weeks: 8 (+ Enables hands-free app navigation for users with visual or mobility challenges; − May require quiet environments and can struggle with diverse accents or speech impairments)
- B) High Contrast and Customizable Text Sizes — feature type: visual enhancement; technical complexity: low; user groups benefited: low vision, color blindness; implementation time weeks: 4 (+ Improves readability for users with visual impairments and personalizes display settings; − Limited benefit for users with cognitive disabilities or those needing alternative input methods)
- C) Real-Time Captioning and Transcripts — feature type: audio accessibility; technical complexity: high; user groups benefited: hearing impaired, non-native speakers; implementation time weeks: 10 (+ Provides immediate text alternatives for audio content, aiding comprehension; − Requires stable internet connection and may have occasional transcription inaccuracies)
- D) Haptic Feedback and Vibration Alerts — feature type: tactile feedback; technical complexity: medium; user groups benefited: hearing impaired, attention deficit; implementation time weeks: 6 (+ Offers non-visual notifications and confirmations to improve user awareness; − Effectiveness varies by device hardware and may not be noticeable in noisy or busy environments)
